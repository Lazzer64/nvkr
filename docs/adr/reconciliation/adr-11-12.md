## Support by owner

|---|---|---|
| 11–12 Resolution | Exact output-selected producers and concrete platforms, including local Darwin ARM64 executable acquisition and explicit Linux-toolchain cross-builds; complete explicit disk material closure; predecessor-bound whole-producer overlays; explicit raw Debian output selection over one ordinary host-package producer; ADR-25 ordinary pinned AICR producers | NVSentinel catalog and private OS placement commands are development inputs; static/controlled checks do not establish fresh product outputs, installation, ABI or runtime acceptance. Local toolchain preparation is compiled by the factory from explicit catalog-name, architecture,
predecessor-pin and component bindings. Every resulting overlay binds the complete selected catalog
digest. The Go launcher (including the active nightly E2E entry point) and ARM64 shell adapter share
this owner, inspect measured local image IDs and platforms, and verify exact output and image-use
coverage after recompilation. Factory contracts cover four independent catalogs, renamed and multiple
disk outputs, missing and ambiguous bindings, unchanged pins and incomplete substitution coverage.
Launcher fixtures cover bootstrap ordering and failure propagation. These checks establish local
wiring contracts; no fresh registry, runner, toolchain build or production acceptance is recorded.

Digest-pinned, explicitly selected catalog fragments share source and component declarations before ordinary
lock resolution. Catalog tests cover aliasing, collisions, unknown inputs, content mutation, pin ownership,
provider admission and resource bounds; factory snapshot tests cover complete capture and replay. These
contracts preserve resolved producer values and do not establish fresh build or runtime acceptance.

Remote base registries (`extends`) are implemented for directory loads, lock maintenance and compile
snapshots. Catalog contracts cover HTTPS URL admission (branch, tag and commit addresses), base fragment and
patch-file digests, command-operand fetches relative to the base, RFC 6902 application and path
confinement, collisions, nested bases, metadata inheritance, provider admission and byte bounds, an
inheritance-free lock over the merged key set, and identity equal to the same base loaded locally.
`TestExtendsNVKEReleaseExample` replays the nvkr v0.1.0 NVKE release base with constraint patches against
its merged lock offline. `TestCompileSnapshotCapturesRemoteBase` covers capture, network-free replay and
missing or tampered remote inputs. Base bytes are deliberately unpinned: no contract detects a moved branch
or tag beyond the merged key set and Plan drift. No maintained catalog extends a remote base and no hosted
Run has loaded one; the providers used by the SDK client and toolchain repinning reject `extends` with
`engine-capability`.
